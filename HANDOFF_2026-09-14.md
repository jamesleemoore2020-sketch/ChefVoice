### Android Live crash: 0.11.5 / 65 — confirmed working

The release crashed in WebRTC JNI initialization. The supplied ARM64 crash log and R8 investigation identified `org/jni_zero/JniInit` being removed even though `org.webrtc` was protected. Added `-keep class org.jni_zero.** { *; }` to `app/proguard-rules.pro`, retained the existing WebRTC dependency, and updated release metadata and four notification source gates. An isolated R8 experiment confirmed the class was retained with the new rule.

Delivered `ChefVoice-Live-0.11.5.patch`. James built the signed production release and confirmed Live worked. AAB SHA-256: `87d83c35a7c04091ef8caf2a3814a0987fa3455298942e0d738eb5a004259797`.

### iPhone/PWA viewer permission failure: 0.4.1 — confirmed working

Firestore security rules were not relaxed or changed.

Delivered `ChefVoice-PWA-Live-0.4.1.patch`. James confirmed the fix after deployment. Five viewer tests use the real Firestore emulator and a simulated RTC engine.

### PWA Go Live: candidate 0.5.0 — locally verified, not deployed

The PWA previously only watched Android broadcasts; there was no hosting button. Added `web/js/webrtc-live-host.js` and integrated a Go Live entry, setup, explicit camera/microphone preview, title/tags, front/back selection before starting, mute, viewer count, reactions, comments, and End controls.

Preview remains private until Go Live is pressed. Hosting uses the existing Android-compatible Firestore SDP/ICE protocol, waits for authorized signaling readiness before publishing LIVE, renews the host heartbeat, and stops capture after a prolonged heartbeat failure. Cancellation, fast viewer rejoin, sign-out, Back/navigation, page hiding, remote session ending, and late permission results release media and listeners. PWA cache/package are now 0.5.0.

No Firestore rules, Functions, Android code, or version metadata are changed by this incremental hosting patch. See `PWA_GO_LIVE_0.5.0.md` for details.
